## 一、系统架构

### 1.1 设计模式

| 模式 | 应用位置 | 说明 |
|------|----------|------|
| 分层架构 | 全局 | 前端展示层 → API 路由层 → Service 业务层 → 数据访问层（SQLAlchemy / qlib bin） |
| 门面（Facade） | `app/services/quant/*` | 封装 qlib 复杂 API，暴露简单评价/回测入口 |
| 工厂 + 策略模式 | `backtest_engine.py` | 按 `backend` 参数选择 qlib / vbt 回测实现 |
| 观察者 / 广播 | `sync_worker.py` + `sync_progress.json` + WebSocket | 子进程进度 → 主进程读取 → 前端实时推送 |
| 线程/进程池 | `app/core/executor.py` | `io_executor`（线程）、`cpu_executor`（进程），`run_io_cpu`/`run_cpu`/`run_mixed` 派发 |
| 单写者（Single Writer） | 因子批量评价 | asyncio.Queue + 单 DB 消费协程，防连接池耗尽 |
| 窄表（EAV） | `macro_indicator` / `financial_indicator` | 指标×报告期×字段 唯一，扩展新指标不改表 |
| 双写存储 | 行情数据 | qlib bin（因子计算）+ PostgreSQL（原始全字段/PIT）各司其职 |

### 1.3 关键机制

- **执行器**：qlib 数据读/因子计算/回测均为 CPU/IO 密集，通过 `run_io_cpu` 派发到线程池（IO 部分）与进程池（CPU 部分），事件循环不被阻塞，`/health` 与其它请求不受影响。
- **同步子进程**：每个同步/修复任务 `spawn_sync_worker` 以独立进程运行（`start_new_session=True`），主进程只读 `data/sync_progress.json`；`sync_lock` flock 串行化所有 baostock 爬虫。
- **日历伸缩**：`day.txt` 增行后所有 bin 必须经 `_pad_bins_to_calendar` NaN 补齐，保证 `4 + 4×len(day.txt)` 字节约束；伸缩期间 `calendar_shifting_active` 置位阻断回测/挖掘。

## 四、核心流程概要

### 4.1 一键全同步（sync-full）

1. 前端「开始同步」→ `POST /quant/data/sync-full?years=N`。
2. 主进程 spawn `kind=full` worker 子进程。
3. 子进程分阶段执行：A 股回填（baostock 按交易日倒序全市场）→ 指数同步 → 宏观同步+广播 → 财报拉取+广播 → 外盘情绪因子；每阶段重设 `worker_pid` 并更新进度。
4. 前端 WebSocket / 轮询 `GET /data/sync-progress` 展示阶段进度。
5. 完成后同步历史落库（`sync_history`），`stock_data_status` 更新。

### 4.2 因子评价（evaluate）

1. 请求 `POST /factors/{id}/evaluate`。
2. 校验表达式（AST 沙箱）→ 经 `run_io_cpu` 派发 qlib 计算。
3. 计算 IC / RankIC / ICIR / 换手 / 多周期 / 正交残差。
4. 结果写回 `factor` 表（ic/rank_ic/icir/turnover/decay/ic_by_horizon/evaluated_at）。

### 4.3 策略回测（backtest）

1. `POST /strategies/{id}/backtest` 携带区间与参数。
2. 按 `backend`（qlib/vbt）创建回测引擎。
3. 经执行器运行；进度经 WebSocket 推送。
4. 结果持久化 `backtest_result`（含参数快照 + 净值曲线/指标/成交 JSON）。

### 4.4 数据校验与修复

1. `GET /data/validate?universe=all` 检查 bin 字段/长度、日历对齐、DB↔bin 覆盖、宏观/财报采样。
2. 问题汇总 → `POST /data/repair`：重建 day.txt、补齐股票 bin、rebroadcast 宏观/财报；可选 baostock 补拉缺失交易日。

### 4.5 AI 因子挖掘（mining）

1. 选择引擎（LLM / 符号回归 / AutoML / 文本）提交任务（限流 3/分钟）。
2. 任务入 `mining_task` 表（pending→running→done/failed）。
3. 执行器运行挖掘；候选因子经筛选（IC 门槛/去重/稳健性）写入 `factor` 表。
4. 结果因子 id 记录 `result_factor_ids`；重启后 pending/running 任务自动恢复。
