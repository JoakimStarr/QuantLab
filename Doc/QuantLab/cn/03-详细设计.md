## 一、数据同步链路详细设计

### 1.1 spawn_sync_worker —— 同步子进程工厂

#### 初始化阶段
1. 校验 kind 合法（backfill/eod/repair/indices/etf/fundamental/macro/full/external_market）。
2. 获取 `sync_lock` flock 爬虫锁（仅 baostock 类任务串行）。
3. 以 `start_new_session=True` 派生子进程，解除与主进程会话关联。
4. 写入初始进度：`{kind, universe, status: "running", worker_pid, stage, ...}` 到 `data/sync_progress.json`。

#### 核心逻辑
1. 子进程内初始化日志与数据库连接，执行对应同步函数。
2. 每完成一个里程碑（交易日/股票/阶段），更新进度 JSON（原子写）。
3. 结束阶段：`finish`（写 ok + 统计）并 `clear` 锁与 pid；若为 `full` 多阶段编排，各阶段完成后重设 `worker_pid` 再进入下一阶段，防止进度被 `clear` 连带清掉而僵尸化。

#### 分支
- 失败：写入 `status: failed` + `error`，`sync_history` 落 failed 记录。
- 幂等：PG 写入全部 `ON CONFLICT DO NOTHING`，重复执行只补缺口。

### 1.2 baostock_backfill —— A 股历史回填

#### 算法流程
1. 由 `years` 与 `trade_calendar` 计算回填日期序列，**最新 → 最旧**逐日处理。
2. 每个交易日调用一次 `query_daily_history_k_AStock` 拉全市场（串行，无并发连接）。
3. `_build_out_df` 输出 19 个 baostock 字段，价格 qfq 复权；`factor=1.0`。
4. 写 qlib bin（原子写 tmp+`os.replace`）+ PG `stock_daily`/`stock_basic`/`stock_industry`/`trade_calendar`。
5. 构建 `instruments/{all,csiall,csi300,csi500,etf_all}.txt`。

#### 关键实现细节
- 并发写盘（多股票分块写 bin）以加速；已下载日期跳过。
- 日历增长时调用 `_pad_bins_to_calendar` NaN 补齐无数据股票。
- 受 baostock ≤50k 请求/日约束，超限错误上抛为可读失败。

### 1.3 eod_incremental —— 增量 EOD

#### 算法流程
1. 读 bin 尾部与 PG `stock_daily` 最大日期，确定缺失区间（最近 N 天）。
2. 对每个缺失交易日拉 baostock/akshare 增量数据。
3. `_sync_stock_bin` 合并写 bin；`_write_calendar` 追加交易日；`_compute_tradable` 重算 `tradable`（涨跌停/ST 5% 掩码）。
4. `_pad_bins_to_calendar`：`day.txt` 扩展后对无数据股票 NaN 补齐，保持 `4 + 4×len(day.txt)` 字节约束。

#### 分支
- 停牌/退市无当日数据：只 pad，不报长度异常。
- 源限制：baostock 串行；akshare 可并行走另一通道。

### 1.4 full_sync —— 一键全同步编排

```
stage1 A股回填 → stage2 指数 → stage3 宏观(拉取+广播)
→ stage4 财报(拉取+广播) → stage5 外盘情绪因子
```
每阶段：独立函数 + 独立进度更新；阶段间重设 `worker_pid`；任一阶段失败标记整体 failed 并保留已成功阶段产物（幂等续跑）。

### 1.5 macro_sync —— 宏观指标同步与广播

1. 东财/akshare 拉取指标（PMI/CPI/PPI/GDP/SHIBOR...）→ PG `macro_indicator` 窄表 `(indicator, report_date, field_name)` 唯一 upsert。
2. 计算 `available_date = report_date + 发布延迟`（PMI 0 / CPI、PPI 9 / GDP 45 天）作为 PIT 锚点。
3. 广播：按 PIT forward-fill 写 `features/{code}/$pmi.day.bin` 等（全股票与指数目录）。

### 1.6 fundamental_sync —— 财报窄表与 PIT 广播

1. akshare 按股票拉财务摘要 → `financial_indicator` 窄表 `(code, report_date, field_name)` 唯一 upsert。
2. **部分抓取防护**：代码仅当已拥有 ≥ 半数 `FIN_FIELD_NAMES` 字段才标记已抓取，否则下次重抓，防止截断响应造成字段永久缺失。
3. 广播：`available_date = report_date + 披露延迟`，PIT forward-fill 写 `$roe`、`$netprofit_yoy` 等 bin 字段。

### 1.7 external_market —— 外盘隔夜情绪因子

1. 拉取美股三大指数（SP500/NASDAQ/...）隔夜涨跌。
2. 计算 `$us_sp500_ret`、`$us_nasdaq_ret` 等因子广播到全部 bin（PIT 对齐到 A 股下一交易日）。

### 1.8 validation —— 数据校验

| 检查项 | 逻辑 |
|--------|------|
| bin 字段 | 每目录校验是否存在 19 个股票字段（指数/ETF 经 `stock_index` 排除） |
| 长度 | `filesize == 4 + 4×len(day.txt)`；不足报「长度异常」 |
| 日历对齐 | day.txt ↔ stock_daily ↔ trade_calendar 对齐 |
| DB↔bin 覆盖 | 股票代码双向比对，缺失列目录 |
| NaN 比例 | 对自身上市区间（stock_daily min/max）度量，规避新 IPO 误报 |
| 宏观/财报采样 | 抽查 bin 中 `$pmi`/`$roe` 等字段存在与数值 |

## 二、因子模块详细设计

### 2.1 expression —— 表达式 AST 沙箱

1. 解析表达式为 AST。
2. 遍历节点：拒绝 `exec/eval/import` 调用；拒绝 `Ref(x, 负周期)`。
3. 通过后允许入库；`uq_factor_expression` 唯一约束防重复。

### 2.2 factor_eval —— 因子评价

#### IC / RankIC / ICIR
1. 经 `run_io_cpu` 在 qlib 上计算因子序列。
2. 与未来收益（horizon 可配）做 Pearson IC 与 Spearman RankIC。
3. ICIR = mean(IC) / std(IC)；IR 类似对收益序列；turnover 由持仓变化率近似。
4. decay：多 lag 的 IC 序列 JSON；ic_by_horizon：多周期 IC JSON。

#### AutoML 表达式兼容
- 遇到 `AutoML(method, fid1, ...)` 表达式时，从 `data/models/automl/{task_id}.pkl` 加载已训练 bundle 计算；`_resolve_task_id_from_factor_ids()` 读取旧 SQLite 映射（SQLite→PG 迁移遗留，后续应改指 PG）。

#### 批量补算（backfill-alpha158-metrics）
- asyncio.Queue 任务队列 + 单个 DB 写协程，串行化写回避免连接池耗尽。

### 2.3 neutralize / orthogonalize

- neutralize：对行业/市值基准回归取残差。
- orthogonalize：Gram-Schmidt 对已有基准因子正交，产出增量 alpha（`orthogonal_ic`）。

## 三、回测模块详细设计

### 3.1 backtest_engine —— 引擎工厂

```
create_backtest_engine(backend)
  ├─ backend == "qlib" → QlibBacktestEngine
  └─ backend == "vbt"  → VbtBacktestEngine
```

### 3.2 qlib_backtest —— qlib 回测

1. 依据 universe + 因子表达式构建数据集（`calendars/day.txt` + `instruments`）。
2. TopK 选股、调仓频率、组合权重（equal/ic/lightgbm/stacking）、基准、正交化。
3. 输出净值曲线、指标（annual_return/sharpe/sortino/max_drawdown/calmar/win_rate...）、逐笔成交（BUY/SELL）。
4. 参数快照持久化到 `backtest_result`。

### 3.3 vbt_backtest —— 规则策略回测

1. 规则表达式（模板化）经 vbt 引擎执行。
2. 信号日成交（ETF 池 T+1 约束在 qlib 端处理，vbt 端按信号日）。
3. 输出与 qlib 引擎同构的绩效/曲线结构，支持对比。

### 3.4 param_sweep —— 参数扫描

1. 候选参数组合笛卡尔积。
2. 精确查重：`(strategy_id, start, end, topk, rebalance_freq)` 命中已存在结果则复用（`idx_backtest_sweep_lookup`）。
3. 并行执行器运行；进度经 `task_result` 表持久化（`task_type=param-sweep`）。

### 3.5 walk_forward —— 滚动验证

1. 按窗口划分训练/验证段，滚动外推。
2. 结果持久化 `task_result`（`task_type=walk-forward`），前端分页展示。

## 四、挖掘模块详细设计

### 4.1 LLM 挖掘（llm_factor）

1. 构造提示词（因子风格/历史候选/强反馈约束）→ 多提供商调用（opencodezen/glm/siliconflow 故障切换）。
2. 生成候选表达式 → AST 沙箱 → 快速 IC 筛选。
3. 通过者入库 `factor`（`source_task_id` 关联），任务状态推进。

### 4.2 符号回归（symbolic）

1. gplearn 演化因子表达式，多目标（IC/复杂度）。
2. 滚动重验 + 行业中性化 + 候选池去重。

### 4.3 AutoML（automl）

1. 基于候选因子自动训练模型 bundle（`data/models/automl/{task_id}.pkl`）。
2. 产出模型因子表达式；重复因子移除并还原原因子指标（rebuild_automl_bundles 脚本兜底）。

### 4.4 文本因子（text_factor）

1. 解析新闻/公告文本 → 情感/主题数值因子。

## 五、任务恢复与调度

### 5.1 recover_stale_sync / recover_stale_mining

- 启动时扫描 `sync_progress.json` 与 `mining_task` 表中 running 且 pid 不存在的任务，标记 failed（stale）。
- `rerun_pending_mining`：将 pending 挖掘任务重新调度执行。

### 5.2 scheduler（APScheduler）

- 每 10 分钟：stale 挖掘回收。
- 每日 18:05：因子衰减检查。
- **无自动数据同步**（手动 API 触发）。

## 六、健康检查与观测

- `_build_health_payload`：DB ping / qlib 可用性 / 调度器运行 / 磁盘剩余 / WS 连接数 / AI Provider key 配置；任一异常 → `degraded`。
- Prometheus `/metrics`：请求量、执行器线程/进程池使用、慢查询。
- 日志：按大小轮转 + 每日清理 + 错误检索接口（`GET /logs`）。

## 七、安全设计

1. 生产安全门禁：`enforce_production_security()` 在 `APP_ENV=production` 且默认密钥时抛错阻断。
2. 生产关闭 Swagger/OpenAPI。
3. SPA 静态文件路径穿越防护（normpath + prefix 校验）。
4. JWT 鉴权依赖 `require_user`（AUTH_ENABLED=false 时放行）；WebSocket 带 token 校验。
5. 统一异常处理：AppError/Validation/HTTP/Starlette 404/405 → `ApiResponse` 信封。
