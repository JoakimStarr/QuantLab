## 一、功能概述

QuantLab 是一个面向个人量化投研的端到端策略研究平台，覆盖「数据 → 因子 → 策略 → 回测 → 挖掘 → 复盘」完整链路：

- **数据层**：通过 baostock / akshare / 东财 datacenter 等公开源，拉取 A 股日 K、指数、ETF、宏观指标、财报数据，以 qlib `.day.bin` 二进制格式与 PostgreSQL 双写存储，提供全量回填、增量 EOD、一键补齐、数据校验等手动数据运维能力。
- **因子层**：因子表达式库（qlib 表达式语法 + AST 沙箱校验），批量评价（IC / RankIC / ICIR / 换手 / 多周期 / 正交残差），内置 Alpha158 因子集导入与补算。
- **策略层**：多因子组合策略（等权 / IC 加权 / LightGBM / Stacking），TopK 选股、调仓频率、基准、正交化开关；参数扫描、Walk-Forward 滚动验证、规则策略回测（vbt 后端）。
- **挖掘层**：AI 因子挖掘，支持 LLM 生成、符号回归（gplearn）、AutoML 自动化、文本因子四种引擎，含候选池筛选、稳健性评估、行业中性化。
- **AI 增强**：因子 AI 解释与追问对话、策略 AI 生成/参数建议/复盘、多 LLM 提供商故障切换。
- **可视化**：Vue 3 前端提供研究首页仪表盘、因子库、策略回测、AI 挖掘、数据管理、宏观指标、因子/回测对比、日志管理等页面；WebSocket 实时推送同步/回测进度。

## 二、功能需求清单

### 2.1 数据管理模块

- 一键全同步（`sync-full`）：A 股回填 → 指数 → 宏观(广播) → 财报(拉取+广播) → 外盘情绪因子，分阶段进度上报。
- 增量 EOD 同步（`eod-sync`）：baostock / akshare 源按最近 N 天增量补齐。
- 指数同步与注册（`sync-indices`）：指数 OHLCV 写入 bin + `stock_index` 表自动注册。
- ETF 同步（`sync-etf`）：全市场 ETF 日 K，腾讯 qfq 对齐回填修正 baostock 不复权口径，限流防护。
- 宏观指标同步（`macro/sync`）：东财 PMI/CPI/PPI/GDP 等 → PG 窄表 → 广播到 qlib bin。
- 财报同步（`fundamental/sync`）：akshare 财务摘要 → `financial_indicator` 窄表 → PIT forward-fill 广播。
- 外盘隔夜情绪因子（`sync-external-market`）：美股三大指数隔夜涨跌广播。
- 数据校验（`validate`）：bin 字段/长度、日历对齐、DB↔bin 覆盖度、宏观/财报字段采样。
- 一键补齐（`repair`）：重建 day.txt 与缺失股票 bin、rebroadcast 宏观/财报；可选包含 baostock 补拉。
- 同步进度 / 历史 / 统计查询；股票搜索；数据预览。

### 2.2 因子库模块

- 因子 CRUD：新增（含 JSON body + 表单弹窗）、列表、详情、软删除（disabled）。
- 因子评价（`evaluate`）：IC/RankIC/ICIR/IR/换手/衰减/多周期，正交后残差 IC。
- 内置因子：Alpha158 种子导入、ETF 因子种子、内建因子列表。
- 批量补算指标（`backfill-alpha158-metrics`）。
- 因子对比（`compare`）、分位数分析、中性化（`neutralize`）、深度分析。
- AI 解释（`ai-explain`）、批量解释、AI 追问对话（`ai-chat`）、AI 详情。
- 因子导出（`export`）、自动导入（`auto-import`）、衰减检查（`decay-check`）。

### 2.3 策略与回测模块

- 策略 CRUD：多因子组合、组合方法、TopK、调仓频率、基准、正交化、AI 偏好。
- 回测执行（`backtest`）：qlib 与 vbt 双后端，参数快照持久化。
- 回测结果：列表、详情、逐笔成交导出、软删除。
- 参数扫描（`param-sweep`）：并行候选组合回测 + 精确查重缓存。
- Walk-Forward 滚动验证（`walk-forward`）。
- 回测对比（`compare-backtests`）、组合报告（`portfolio-report`）。
- 规则策略回测（`strategy_rule`）：模板 + 规则表达式回测（vbt）。
- AI：策略生成（`ai/generate`）、参数建议（`ai/params`）、复盘（`ai/review`）。

### 2.4 AI 因子挖掘模块

- LLM 挖掘（`/mining/llm`）、符号回归（`/mining/symbolic`）、AutoML（`/mining/automl`）、文本因子（`/mining/text`），均限流 3/分钟。
- 任务列表 / 详情 / 结果；挖掘模板列表与运行。
- 任务持久化：运行中恢复、stale 回收、pending 重跑。

### 2.5 系统与运维模块

- 健康检查（`/health` + `/api/v1/health`）：DB / qlib / 调度器 / 磁盘 / WebSocket / AI Provider。
- 日志：文件列表、检索、清空（按大小轮转 + 定期清理）。
- 鉴权：JWT 登录/状态/用户信息，`AUTH_ENABLED` 开关。
- Prometheus `/metrics`；慢查询与执行器指标。
- 前端技术文档页（`/docs`）、系统配置读取。

### 2.6 前端页面

- Dashboard（研究首页）、FactorLibrary（因子库）、Strategy（策略回测）、StrategyLibrary（策略库）、Mining（AI 因子挖掘）、DataStatus（数据管理）、Macro（宏观指标）、FactorCompare（因子对比）、BacktestCompare（回测对比）、FactorDeepAnalysis（因子深度分析）、Docs（技术文档）、Logs（日志管理）、Login（登录）。

## 三、业务规则需求

### 3.1 数据同步规则

- 数据同步**仅手动触发**，启动/定时器不做自动同步，保证启动快、`/health` 即时响应。
- 同步以**独立 worker 子进程**运行（每 kind 一个进程），禁用作 FastAPI `BackgroundTasks`（避免 uvicorn `--reload` 挂起）；进度经 `data/sync_progress.json` 桥接。
- baostock 爬虫受 `sync_lock` flock 串行化；遵守 ≤50k 请求/日、无并发连接限制。
- 全同步链 `full` 每阶段结束后重设 `worker_pid`，防止阶段切换时进度僵尸化。
- 财报部分抓取防护：代码仅在拥有 ≥ 半数 `FIN_FIELD_NAMES` 时才视为已抓取，避免字段永久缺失。

### 3.2 数据存储规则

- 每只股票 bin 长度必须恒等于 `4 + 4×len(day.txt)` 字节；`day.txt` 增长后，对无数据股票调用 `_pad_bins_to_calendar` NaN 补齐。
- bin 写入原子化（临时文件 + `os.replace`）；日历伸缩类同步期间置 `calendar_shifting_active`，阻塞回测/挖掘。
- `factor` bin 恒为 1.0（价格以 qfq 复权存储，qlib 依赖 `$factor` 识别复权口径）。
- 指数/ETF 是独立 instrument 类：只写 OHLCV，无 stock_daily/财报，校验与补齐经 `stock_index` 表排除。

### 3.3 因子与回测规则

- 因子表达式须通过 AST 沙箱校验：拒绝 `exec/eval/import` 与负周期 `Ref`；同一表达式全局唯一（`uq_factor_expression`）。
- 因子评价与回测为 CPU/IO 密集型，一律经 `run_io_cpu`/`run_cpu` 线程/进程池派发，不阻塞事件循环。
- 回测结果持久化参数快照（v2.4.1 起），保证每条结果自带完整配置；参数扫描按「策略×区间×参数组合」精确查重缓存。
- 回测结果软删除（`is_deleted` 标记），保留审计。

### 3.4 安全规则

- 生产环境（`APP_ENV=production`）下默认 `SECRET_KEY` / `ADMIN_PASSWORD` 直接阻断启动（安全门禁）。
- 生产环境关闭 `/docs`、`/redoc`、`/openapi.json`。
- 统一响应信封 `ApiResponse {ok, data, error}`；错误码 `VALIDATION_ERROR / NOT_FOUND / QLIB_NOT_AVAILABLE / SYNC_IN_PROGRESS / AUTH_FAILED`。

## 四、非功能需求

### 4.1 性能要求

- 启动链路保持轻量：lifespan 只做日志/鉴权/建表/状态恢复/调度器，不做重计算；`/health` 立即响应。
- 因子批量评价使用 asyncio.Queue + 单 DB 写线程，避免连接池耗尽。
- 长同步（全量回填等）在独立 worker 子进程内执行，主进程只读进度文件。
- 前端 Dashboard 懒加载、因子列表 5 分钟缓存。

### 4.2 可用性要求

- 同步进度实时上报（sync_progress.json + WebSocket 推送）；失败可重试且幂等（`ON CONFLICT DO NOTHING`）。
- 异常同步/挖掘任务在重启时自动恢复（recover_stale_sync / recover_stale_mining），pending 挖掘自动重跑。
- 数据校验能区分「长度异常」与「字段缺失」两类问题，并给出可修复项。

### 4.3 安全要求

- JWT 鉴权（AUTH_ENABLED 可关），WebSocket 带 token 校验。
- 前端 SPA 静态文件路径穿越防护（normpath + startswith 校验）。
- 日志分级、轮转、错误检索；敏感配置（API key）存于 `.env`，不落库不入库。
