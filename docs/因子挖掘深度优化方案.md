# 因子挖掘深度优化方案

> 生成日期：2026-08-03
> 定位：在现有 LLM/符号回归/AutoML 挖掘基础上，提升因子质量与可信度
> 关联：`docs/QuantLab_AI策略与因子挖掘完整优化方案.md`（全局路线图）

---

## 一、现状与问题

| 现状 | 问题 |
|------|------|
| 评价 horizon 固定 5 天 | 漏掉短/长周期有效的因子 |
| 单次样本分割 (60/20/20) | 静态分割，抗过拟合弱 |
| 挖掘在原始字段上进行 | 重复已有因子的风险 |
| LLM 每次现场生成表达式 | 结果不稳定，废品率高 |
| 挖掘任务无实时日志 | 用户不知道卡在哪步 |
| 达标因子自动入库 | 无人工审核环节 |

## 三、详细设计

### 1. 多周期评价（P0）

**现状**: `factor_eval.py:397` `horizon = settings.mining.get("llm", {}).get("eval_horizon", 5)`,固定 5 天。

**方案**: 评价时对多个 horizon 计算 IC,输出每个周期的 IC/ICIR,并给"多周期稳定度"指标。

```
horizons = [1, 5, 10, 20]
for h in horizons:
    label = f"Ref($close, -{h}) / $close - 1"
    ic_h = compute_ic(factor_df, load_label(...h...))
```

**输出扩展**:
```json
{
  "ic": 0.05,           // 主 horizon (5天)
  "ic_by_horizon": {    // 多周期 IC
    "1": 0.02, "5": 0.05, "10": 0.06, "20": 0.04
  },
  "multi_horizon_stability": 0.75  // 各周期 IC 同号比例
}
```

**筛选增强**: 主 IC 达标 + 至少 3 个周期同号,才算"稳定因子"。

**涉及文件**:
- `app/services/quant/factor_eval.py`: `evaluate_factor` 增加 `horizons` 参数
- `app/services/factor/library.py`: `update_factor_metrics` 增加字段
- 迁移: `factor` 表加 `ic_by_horizon` (Text JSON)

### 2. 滚动窗口重验（P1）

**现状**: `SampleSplitter` 静态分割 60/20/20。

**方案**: 增加滚动验证:
```
窗口 1: [1..N1] 训练, [N1..N2] 验证
窗口 2: [k..N1+k] 训练, ...
```
对每个窗口计算 valid_ic,取中位数作为稳健 IC。

**实现**: 复用 `walk_forward.py` 的滚动逻辑(已存在),新增 `compute_rolling_valid_ic()`。

### 3. 子样本稳健性（P1）

**方案**: 因子 IC 按以下维度分组统计:
- 时间: 上半年/下半年
- 市值: 大/中/小 (用 `$amount` 或市值代理)
- 行业: 各行业 IC

**输出**: `robustness = {time: {...}, mktcap: {...}}`,用于识别"只在特定环境有效"的因子。

### 4. 正交后挖掘（P0）

**现状**: LLM 直接从原始字段生成,可能与已有高 IC 因子高度相关。

**方案**: 挖掘前先把已有高 IC 因子(如 Alpha158 达标子集)作为基准,挖出的候选因子做正交化后再评价:

```
候选因子 → 对基准因子回归 → 残差作为"增量因子" → 评价残差 IC
```

**实现**: 复用 `orthogonalize.gram_schmidt_orthogonalize()`。

**涉及文件**:
- `app/services/quant/factor_eval.py`: 增加 `baseline_factor_ids` 参数
- `app/services/mining/llm_factor.py`: 挖掘时加载基准因子

### 5. 行业中性化挖掘（P1）

**方案**: 候选因子评价前先做行业中性化,避免行业暴露造成的假 IC。

**实现**: 复用 `neutralize.industry_neutralize()`,需要行业数据(`stock_industry` 表,已入库)。

### 6. LLM 强反馈迭代（P1）

**现状**: `iterative_mine_factors` 3 轮,反馈较温和。

**方案**: 增强反馈:
- 每轮把"被沙箱拒绝的表达式 + 原因"也反馈给 LLM
- 若上一轮全部 IC < 阈值,明确要求"改变策略,不要重复类似结构"
- 每轮动态调整生成的因子风格占比

### 7. 基本面因子（P1, 依赖财务回填）

**前提**: 先完成 `fin_*` 财报回填。

**新增因子类型**:
- 质量: ROE、毛利率、净利率
- 成长: 营收/净利增速
- 估值: 结合已有 pe/pb 做分位

**实现**: 新增 `fundamental_factor.py` 服务,从 PG fin_* 表构造因子面板,对齐到日频。

### 8. 技术指标候选池（P1）

**方案**: 预置经典技术指标 qlib 表达式,作为挖掘候选池(LLM 从中选/组合):
- RSI: `Mean(Max($close-Ref($close,1),0),14)/Mean(Abs($close-Ref($close,1)),14)*100`
- MACD: EMA 差
- 布林带: `($close-Mean($close,20))/(2*Std($close,20))`

**实现**: `backend/app/services/mining/indicator_pool.py` 新建,存 ~50 个表达式。

### 9. 情绪/资金流因子（P2）

**方案**: 用已有 `$turn`(换手)、`$amount`、`$change`、`$tradable` 构造:
- 换手异动: `Rank($turn) - Rank(Mean($turn,20))`
- 量价配合: `Corr($close, $volume, 10)`
- 涨跌停信号: `$tradable == 0`

### 10. 候选池预生成（P1）

**方案**: 预生成 500+ 常用因子表达式(含 indicator_pool + Alpha158 子集 + 基础组合),挖掘时:
- LLM 从候选池挑选/变体,而非完全现场生成
- 提高命中率,减少无效调用

**实现**: `candidate_pool.py` 新建,提供 `get_candidates(style, n)`。

### 11. 并行评测扩展（P2）

**现状**: `run_cpu` 进程池并行 IC 评价。

**方案**: 配置化 `max_workers`,按机器核数扩展;支持批量表达式一次 qlib 加载(减少重复 IO)。

### 12. 结果去重增强（P0, 已有基础）

**现状**: `_is_duplicate` 字符串相似度去重 + `compute_existing_ic_series` 相关度去重。

**方案**: 入库前强制检查:
- 表达式字符串相似度 > 0.9 → 拒
- 与已有因子 IC 序列相关 > 0.8 → 拒
- 输出去重原因(方便前端展示)

### 13. 故事因子沉淀（P1）

**方案**: 增加"研究案例"功能:
- 从挖掘结果选择 2-3 个 IC 显著因子
- 自动生成「假设 → 构造 → IC 验证 → 稳健性 → 回测」完整报告
- 存为可展示的案例页(面试用)

**实现**: `case_study.py` 服务 + 前端案例页。

### 14. 挖掘日志可视化（P2）

**方案**: MiningTask 增加 `log_events` 字段,记录:
- LLM 调用开始/返回
- 每个候选的沙箱校验结果
- 每个候选的 IC 评价结果
- 拒绝原因

前端挖掘页展示实时日志流。

## 六、收益

| 维度 | 当前 | 优化后 |
|------|------|--------|
| 因子可信度 | 单周期 + 静态分割 | 多周期 + 滚动验证 + 子样本稳健 |
| 因子独立性 | 可能重复 | 正交化保证增量 alpha |
| 挖掘命中率 | LLM 现场生成,低 | 候选池 + 强反馈,高 |
| 可解释性 | 表达式 | 表达式 + 稳健性报告 |
| 作品集价值 | 中 | 高(可展示完整验证链) |
