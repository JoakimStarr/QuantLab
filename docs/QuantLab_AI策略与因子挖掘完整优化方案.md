# QuantLab AI 策略与因子挖掘完整优化方案

> 生成日期：2026-08-03
> 定位：把 QuantLab 从"因子研究平台"升级为"AI 驱动的因子→策略→复盘闭环"
> 目标：求职作品集完整性 + 可验证的因子策略体系

---

## 一、现状盘点

### 1.1 已完成能力
| 模块 | 状态 |
|------|------|
| 数据同步 | baostock 全量回填(18字段, 含估值/换手) |
| 因子评价 | IC/RankIC/ICIR/换手/衰减 + 样本分割 + Newey-West 显著性 |
| 因子挖掘 | LLM 挖掘 / 符号回归 / AutoML 三种 |
| 回测 | qlib 引擎 + VectorBT |
| 交叉验证 | purgedcv 库 + walk-forward |
| 组合优化 | skfolio |
| 绩效报告 | empyrical + quantstats |
| AI 基础设施 | 多提供商路由 + failover + 预算控制 |

### 1.2 关键短板
1. **数据只有 1 年** — 统计功效不足,因子存活率虚高
2. **特征单一** — 只有日线+估值,缺基本面(营收/利润/ROE)
3. **无 AI 策略生成** — 策略靠手动配置,AI 只参与因子侧
4. **无 AI 策略复盘** — 回测结果无文字解读
5. **挖掘同质化** — 候选因子容易全是价格动量变体

---

## 二、总体架构（升级后闭环）

```
数据层 → 因子层 → 策略层 → 复盘层 → 前端
         ↑        ↑        ↑
         └────────┴────────┘  ← AI 贯穿全链路
```

**AI 完整闭环**:
1. **AI 挖因子**:LLM/符号回归/AutoML 生成候选 → IC 评价 → 入库
2. **AI 组策略**:LLM 参考因子评价 + 相关性,自动推荐因子组合与参数
3. **AI 跑验证**:walk-forward / purged CV 验证策略稳健性
4. **AI 做复盘**:LLM 解读收益曲线/回撤/持仓,生成文字报告

## 四、Phase 3 详细设计（核心）

### 3.1 AI 生成策略

**输入**:
- 因子库中已达标因子(IC/ICIR/显著性)及其评价指标
- 因子间相关性矩阵
- 用户可选约束(股票池、回测区间)

**流程**:
```
1. 后端收集因子评价数据,格式化给 LLM
2. Prompt 要求:选择 2-5 个低相关、IC 互补的因子
   推荐 topk/n_drop/调仓频率,说明理由
3. LLM 返回 JSON: {factor_ids, topk, n_drop, rebalance_freq, rationale}
4. 后端校验因子存在性 + 自动创建策略
5. 可选:自动触发参数扫描对比
```

**Prompt 要点**:
- 给 LLM 因子 IC/ICIR/相关性矩阵(结构化数据)
- 要求遵守因子组合规则(低相关、正 IC、不过度集中)
- 输出 JSON 保证可解析

### 3.2 AI 参数建议

**输入**: 选定的因子组合 + 历史回测结果
**输出**: 推荐的 topk/n_drop/调仓频率范围 + 依据

### 3.3 AI 策略复盘

**输入**: 回测结果(收益曲线/回撤/换手/持仓/基准对比)
**流程**:
```
1. 计算关键指标(总收益/年化/夏普/最大回撤/胜率/换手)
2. 提取关键节点(最大回撤段、超额收益段、调仓频繁期)
3. LLM 生成结构化复盘报告:
   - 策略表现总评
   - 收益来源分析
   - 风险点(回撤集中在哪段,为何)
   - 优化建议(调参方向/因子调整/风控)
4. 存库 + 前端展示
```

```
backend/app/services/strategy/
  ai_strategy.py        # 新: AI 生成策略/参数建议/复盘
  ai_prompts.py         # 新: 策略相关 prompt 模板
backend/app/services/ai/
  provider_router.py    # 复用: 多提供商路由
```

### 5.4 复用现有基础设施

- `mining_task` 模型 — 记录 AI 任务状态
